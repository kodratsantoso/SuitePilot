# Skill: SuiteScript Helper

## Purpose

Generate SuiteScript 2.1 code scaffolds for common NetSuite script types. Scaffolds include correct module declarations, entry point functions, error handling patterns, and TODO placeholders for business logic. All generated code is a draft for technical consultant review — it must never be deployed to production without review.

## When To Use

Use when a technical consultant needs a starting scaffold for a SuiteScript 2.1 script: User Event, Client Script, Map/Reduce, Scheduled Script, Suitelet, or RESTlet. Also use to generate documentation for existing scripts or to identify improvement areas in provided script descriptions.

## Required Inputs

- Script type (User Event / Client Script / Map/Reduce / Scheduled / Suitelet / RESTlet)
- SuiteScript version (always 2.1 unless explicitly justified)
- Purpose of the script (what business problem it solves)
- Record type(s) involved
- Entry points needed (e.g., beforeSubmit, afterSubmit, scheduled execute, map/reduce stages)
- Modules required (e.g., N/record, N/search, N/email, N/log)
- Key business logic to implement (in plain English; the scaffold will add TODOs)
- Error handling requirements
- Logging requirements

## Process

1. Declare the script with correct `@NApiVersion 2.1` and `@NScriptType` JSDoc annotations.
2. Define the required modules in the `define` array.
3. Structure the entry point functions for the requested script type.
4. Add structured error handling (try/catch with N/log logging).
5. Add TODO comments where business logic must be implemented by the developer.
6. Add a script header with purpose, author placeholder, and draft status warning.

## Output Format

```javascript
/**
 * @NApiVersion 2.1
 * @NScriptType [ScriptType]
 *
 * [Script Name] — DRAFT
 * Purpose: [Purpose description]
 * Status: DRAFT — Must be reviewed by Senior Technical Consultant before deployment
 *
 * Generated by AI Technical Consultant Agent.
 * Review all TODOs before deploying to any NetSuite environment.
 */
define(['N/record', 'N/log', 'N/error'], (record, log, error) => {

  // ── Entry Point ──────────────────────────────────────────────────────────
  const [entryPoint] = (context) => {
    try {

      // TODO: Implement business logic here
      // TODO: Replace all placeholder values before deployment

      log.debug({ title: '[Script Name]', details: 'Entry point invoked' });

    } catch (e) {
      log.error({ title: '[Script Name] Error', details: e.message });
      throw e;
    }
  };

  return { [entryPoint] };
});
```

## Validation Rules

- Must use `@NApiVersion 2.1`
- Must include a DRAFT warning in the JSDoc header
- Every entry point must have a try/catch block
- Every catch block must call `log.error` before re-throwing
- TODO comments must be present wherever business logic is needed
- N/log must always be included in the module list

## Risk Checks

- Flag if the script type is User Event and the developer is attempting to perform async operations (not supported in User Event beforeLoad/beforeSubmit)
- Flag if a Scheduled Script is being used for real-time processing (wrong tool)
- Flag if N/search is used without result pagination for potentially large datasets (governance risk)
- Flag any use of `nlapiLoadRecord` or other `nlapi*` functions — these are deprecated, use N/record API

## Do Not Do

- Do not generate complete business logic — only scaffolds with TODOs
- Do not use SuiteScript 1.0 (`nlapi*`) APIs
- Do not omit the DRAFT warning
- Do not suggest deploying to production before review
- Do not skip error handling

      const status = context.newRecord.getValue({ fieldId: 'orderstatus' });

      if (status !== 'B') return;

      // TODO: Get recipient email from Sales Rep field or configuration
      const recipientEmail = 'TODO@example.com';

      email.send({
